# Role: QA

> **Owner:** [@nicolasrufino](https://github.com/nicolasrufino) · **Last reviewed:** Sep 29, 2026 · **Audience:** QA members · **Type:** Tutorial

You make sure what ships works before members see it. No coding needed to start.

| Step | What |
|---|---|
| 1 | Take a PR or an area from your team's issues |
| 2 | Test it at desktop and phone width, keyboard only, and with empty/error cases |
| 3 | Report each problem as an issue: **Page · Did · Saw · Expected**, with a screenshot |
| 4 | Re-test when the fix lands and close the issue |

Good QA is specific: one issue per problem, reproducible in under a minute.
